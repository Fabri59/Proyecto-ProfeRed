INSTRUCCIONES PARA EJECUTAR EL PROYECTO LOCALMENTE

Resumen rápido:
- Backend: .NET 8 API en `backend/PlanEstrategico.API` (escucha en http://localhost:5000)
- Frontend: Vite + React en `frontend` (http://localhost:5173)
- Base de datos: SQL Server (Express / LocalDB). Los scripts están en `database/`

1) Pre-requisitos (instalar en la PC destino)
- .NET SDK 8+ (dotnet)
- SQL Server (Express) o LocalDB con `sqlcmd` disponible
- Node.js 18+ y npm

2) Descomprimir el proyecto y abrir PowerShell en la carpeta raíz del proyecto (la que contiene `Proyecto.sln`).

3) Base de datos
(Opciones: ejecutar scripts con SQL Server Management Studio o `sqlcmd` con autenticación Windows)

Usando `sqlcmd` (PowerShell) — adapta la ruta según donde descomprimiste:

```powershell
# Crear BD + tablas (si no existe)
sqlcmd -S localhost -E -i "C:\ruta\a\Proyecto\database\01_create_database.sql"
# Crear procedimientos y vistas
sqlcmd -S localhost -E -i "C:\ruta\a\Proyecto\database\02_stored_procedures.sql"
```

Si usas LocalDB, ajusta la conexión en `backend/PlanEstrategico.API/appsettings.json` a:

```
"DefaultConnection": "Server=(localdb)\\MSSQLLocalDB;Database=PlanEstrategicopTI;Trusted_Connection=true;TrustServerCertificate=true;MultipleActiveResultSets=true"
```

4) Backend (.NET)

Desde PowerShell (en la raíz del proyecto):

```powershell
cd backend\PlanEstrategico.API
dotnet restore
dotnet build
# Para desarrollo con Swagger habilitado:
$env:ASPNETCORE_ENVIRONMENT='Development'
# Ejecutar (aplica migraciones automáticas)
dotnet run
```

- Si la migración falla por conexión, asegúrate de que SQL Server está corriendo y la cadena de conexión apunta a la instancia correcta.
- Swagger (si `ASPNETCORE_ENVIRONMENT=Development`) estará en: http://localhost:5000/swagger

5) Frontend (Vite)

En otra terminal PowerShell:

```powershell
cd frontend
# Si hay conflictos de peer deps, usar --legacy-peer-deps
npm install --legacy-peer-deps
npm run dev
```

- Frontend disponible en: http://localhost:5173/
- Si el frontend necesita apuntar a la API, crea un archivo `.env` en `frontend` con:

```
VITE_API_URL=http://localhost:5000/api
```

6) Crear usuario administrador (opcional)

Opción A — usando API (más simple):

```powershell
Invoke-RestMethod -Uri http://localhost:5000/api/auth/register -Method Post -ContentType 'application/json' -Body '{"nombre":"Admin","email":"admin2@empresa.com","nombreUsuario":"admin2","password":"123456"}'
# Asignar rol Admin (si la tabla Roles ya contiene Administrador con IdRol=1):
sqlcmd -S localhost -E -Q "USE PlanEstrategicopTI; UPDATE dbo.Usuarios SET IdRol = 1 WHERE Email = 'admin2@empresa.com';"
```

Opción B — insertar por SQL (si prefieres): usa el hash bcrypt provisto en el proyecto (ejemplo en QUICKSTART.md):

```powershell

```

7) Pruebas básicas

- Hacer login (PowerShell):

```powershell
Invoke-RestMethod -Uri http://localhost:5000/api/auth/login -Method Post -ContentType 'application/json' -Body '{"email":"admin2@empresa.com","password":"123456"}'
```

- Cargar frontend en el navegador: http://localhost:5173/
- Usar token JWT retornado para llamadas a la API protegidas.

8) Problemas comunes y soluciones rápidas
- Error de conexión SQL: verifica que el servicio "SQL Server (MSSQLSERVER)" o instancia `SQLEXPRESS` está corriendo y el `DefaultConnection` apunta a la instancia correcta.
- Si el puerto 5000 está en uso, cambia el puerto en `Program.cs` o ejecuta `dotnet run --urls "http://localhost:5001"`.
- Problemas con dependencias npm: `npm install --legacy-peer-deps`.
